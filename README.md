# 🎲 营销活动抽奖与积分激励运营平台

基于 **Vue 3 + Vite + Pinia** 的营销运营平台，覆盖抽奖玩法、积分体系与运营管理。

## 功能特性

- **多玩法抽奖**
  - 🎡 幸运转盘（SVG 扇形 + 旋转动画）与 🎰 刮刮乐（Canvas 刮涂层揭晓）
  - 加权随机抽取、奖品库存扣减、积分奖品自动入账
- **抽奖任务自动结算**：任务进度按真实参与记录累计（正常 + 审核放行计入；风控冻结暂缓、撤销不计），达标自动发奖并同步积分流水；风控放行后按记录归属业务日补计、撤销后确认回退；任务进度与领奖记录按业务日归档台账，跨日审核不串账、不重复发奖
- **风控校验**：每日限抽 / 累计限抽 / 奖品库存余量 / 积分不足拦截
- **风控申诉**：抽奖与兑换命中可配置规则时生成风险审核单，冻结相关积分、预占奖品/商品库存；用户可申诉，运营审核后放行（发奖/核销）或撤销（返还积分/库存/次数）；角色权限 + 全量操作记录，状态机保证幂等防重复扣减
- **积分体系**：签到与任务赚积分、积分明细流水（含冻结/返还/放行/任务结算标记）、积分商城兑换
- **运营侧**：运营看板（累计抽奖、参与人数、中奖统计、库存、待风控/冻结积分、任务结算量）、活动管理（新建 / 暂停 / 重置库存 / 删除）
- **演示友好**：内置多套 mock 活动、预置用户积分、预置风控审核单（待审/已申诉/已放行/已撤销/跨日待审）与历史业务日任务台账，纯前端零后端即可浏览运行

## 抽奖任务自动结算说明

- **进度来源**：抽奖任务（如「今日抽奖3次」）进度唯一来源于真实参与记录——状态为 `正常` 与 `已放行` 的抽奖记录计入；`冻结` 暂缓计入，`撤销` 不计入。无手动领取入口，杜绝刷任务与重复发奖。
- **自动结算**：每次有效参与落账后按归属业务日结算，达标即自动发放奖励并写入积分流水（`任务结算：xxx`）；同一（任务 × 业务日）仅发奖一次（`taskClaims` 台账判重，重复触发幂等跳过）。
- **风控联动**
  - 冻结：该笔暂缓计入，任务页与审核单均提示"审核中暂缓"；
  - 放行：按参与记录的**归属业务日**补计进度，若达标自动补发奖励（流水与台账标注"跨日补计"），不计入审核当日，避免跨日串账；
  - 撤销：该笔确认不计入（冻结期未计入，撤销后自然回退），积分/库存/限次按既有规则返还。
- **按业务日归档**：积分中心「任务结算记录」按业务日分册展示每日进度、审核中笔数与领奖记录（含归属日/发放日）；业务日切换时先兜底结算上一日再归档，历史台账保留不丢。
- **同步积分流水**：任务奖励实时入账并写 append-only 流水；跨日补计的流水日期为实际发放日、备注归属业务日，保证账实一致。
- 逻辑冒烟测试：`npm run test:settle`（覆盖进度累计/冻结暂缓/放行补计/撤销回退/幂等防重/跨日隔离）。

## 风控申诉说明

- **可配置规则**（「🛡️ 风控申诉」运营视角配置，即时生效）：高价值奖品稀有度、当日抽奖频次、短时连抽/连兑窗口、高价值兑换积分阈值、用户黑名单、风控总开关
- **审核单状态机**：`待审核 pending → 已申诉 appealed → 已放行 released / 已撤销 revoked`，仅待处理态可申诉/审核，重复提交自动拦截
- **冻结语义**
  - 积分：抽奖/兑换成本即时从可用余额转入冻结；放行则核销为消费（积分奖品此时才入账），撤销则原路返还
  - 库存：奖品/商品 `remain -1` 同时 `frozen +1` 预占（不超卖）；放行核销预占，撤销回补
  - 限次：冻结抽奖占用每日/累计次数，撤销后返还
- **权限**：用户仅能对本人单据申诉；仅运营可放行/撤销/配置规则（页内可切换演示视角）
- **审计**：冻结、申诉、放行、撤销、规则变更、视角切换全部写入操作记录；积分流水 append-only，业务记录与看板统计随审核结果同步
